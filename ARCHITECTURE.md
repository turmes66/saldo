# Сальдо — бизнес-архитектура

Прототип личного кабинета учёта денежных средств (`index.html` + `app.js` + `styles.css`).  
Документ описывает **текущую** модель продукта: роли, контуры, сущности, жизненные циклы и права — по фактической логике в коде.

---

## 1. Как устроены роли

В Сальдо **две роли**. Отдельных «уровней компании / проекта» нет.

1. **Администратор** — управляет людьми и справочниками, ведёт выдачи и поступления организации, смотрит движение ДС, согласовывает **отчёты** и **приходы пользователей**, смотрит журнал действий.
2. **Пользователь** — работает со **своими** средствами и **своими** документами: смотрит поступления (выдачи), возвращает остаток, регистрирует бизнес-приходы, создаёт и отправляет отчёты, смотрит сводку своих отчётов.

У каждого сотрудника в системе ровно **одна** роль: либо Администратор, либо Пользователь.

В данных роль хранится по-русски (`«Администратор»` / `«Пользователь»`); в рантайме сессии — `state.role`: `admin` | `user`.

### Примеры

- Администратор может выдать деньги пользователю, принять возврат, утвердить или отклонить отчёт, принять приход (сразу в ДС или «к сдаче») — но не «живёт» в чужом личном остатке как в кабинете пользователя.
- Пользователь может отчитаться по своей выдаче и вернуть остаток, зарегистрировать приход денег бизнеса — но не может добавлять пользователей, сбрасывать пароль, править справочники или согласовывать чужие отчёты и приходы.

### Что настраивает бизнес

Сейчас набор возможностей у ролей **фиксированный** (зашит в продукт):

- что может Администратор;
- что может Пользователь.

Отдельной матрицы «галочек прав» в интерфейсе нет: роль выбирается при создании / редактировании пользователя, и от неё зависит доступный функционал.

### Что зашито в системе и не настраивается

- нет саморегистрации и самовосстановления пароля — доступ выдаёт администратор;
- пароли выдаёт / сбрасывает администратор (точечно или всем);
- администратор может принудительно завершить сессию одного пользователя или всех (кроме себя);
- пользователь видит и меняет только **свои** данные (средства, приходы, отчёты);
- удаление сущностей учёта **не используется** — применяется **архивирование** (исключение: автор может удалить **свой черновик** отчёта или прихода);
- зарплата, премии и личные доходы сотрудника **вне продукта**.

### Как этим пользоваться

1. При создании человека администратор выбирает роль: **Администратор** или **Пользователь**.
2. Права не смешиваются: роль Пользователь не даёт админ-операций; роль Администратор не подменяет личный кабинет сотрудника.
3. Смена роли — только у администратора в разделе **«Пользователи»**.

## 2. Контуры продукта

Три денежных контура + справочники и доступ.

| Контур | Смысл | Кто ведёт |
|---|---|---|
| **A. Выдача → расход / возврат** | Деньги организации у сотрудника под отчёт | Админ выдаёт; пользователь отчитывается / возвращает остаток |
| **B. Приходы (бизнес через сотрудника)** | Деньги бизнеса, которые сотрудник **принял** и регистрирует | Пользователь создаёт; админ принимает / отклоняет / отражает в ДС |
| **C. Поступления организации (касса админа)** | Приход в «кассу» админа: от компаний, возвраты от пользователей, зачисления по приходам | Только администратор |
| **Справочники / доступ / аудит** | Компании, процедуры, назначения, статьи; пользователи; журнал | Администратор |

Контуры **не смешиваются**:

- выдача ≠ приход, зарегистрированный пользователем;
- «Зарегистрировать приход» ≠ личный дневник доходов;
- компенсация «из своих» идёт через **отчёт**, не через приход;
- зачисление прихода в ДС создаёт **поступление** (контур C), но **не** списывает остаток выдачи.

```text
Организация
├── Админ: выдача сотруднику ─────────────┐
│                                         ▼
│                              Пользователь: остаток по поступлениям
│                                         │
│                    ┌────────────────────┼────────────────────┐
│                    ▼                    ▼                    ▼
│              отчёт из выдачи      возврат остатка     приход (бизнес)
│                    │                    │                    │
│                    ▼                    ▼                    ▼
│              согласование          поступление     проверка → К сдаче
│              отчёта (админ)        у админа (C)         или сразу
│                                                         Зачислен + (C)
│
└── Админ: поступление от компании / прочее (контур C)
```

## 3. Навигация (как в UI)

### Администратор

| Раздел меню | Содержание |
|---|---|
| *(логотип → Главная)* | Сводка: пользователи, остатки, приходы на проверке, отчёты на проверке |
| **Выдача денежных средств** | Выдачи сотрудникам / компаниям, архив |
| **Получение денежных средств** | Два блока (по умолчанию свёрнуты): **Приходы пользователей** (согласование) и **Поступления администратору** (касса) |
| **Движение денежных средств** | Реестр движений за период (активные выдачи и поступления) |
| **Отчёты** | Согласование отчётов сотрудников (чужие черновики скрыты) |
| **Пользователи** | Карточки, роли, пароли, блокировка, кик сессий |
| **Справочники** | Компании, процедуры, назначения платежа, статьи расходов |
| **Журнал действий** | Аудит по системе |

Отдельной вкладки **«Приходы»** нет: согласование приходов — внутри **«Получение денежных средств»**.

### Пользователь

| Раздел меню | Содержание |
|---|---|
| *(логотип → Главная)* | Краткая сводка по своим средствам и отчётам |
| **Мои средства** | Блок **Поступления** (выдачи + остатки, возврат, архив) и блок **Приходы** (регистрация и статусы) |
| **Создание отчётов** | Черновики, отправка, доработка |
| **Сводка отчётов** | Просмотр своих отчётов |

У пользователя **нет** разделов: Пользователи, Справочники, Выдача/Получение «от организации», Движение ДС, Журнал действий.

## 4. Список прав по ролям

### Администратор

**Пользователи**

- Просмотр списка пользователей
- Создание пользователя и выдача пароля
- Редактирование карточки и роли
- Блокировка / разблокировка пользователя
- Сброс пароля (одному)
- Сброс паролей всем
- Принудительный выход (одного)
- Принудительный выход всех (кроме себя)

**Справочники**

- Просмотр и ведение компаний, процедур, назначений платежа, статей расходов
- Архивирование / восстановление записей справочника  
  *(справочник «Статьи расходов» есть в UI; в формах выдач / отчётов / приходов пока почти не задействован)*

**Денежные операции организации**

- Создание и просмотр выдач (целевая / нецелевая; получатель — пользователь или компания)
- Архивирование / восстановление выдач
- Создание и просмотр поступлений в кассу (в т.ч. возврат от пользователя **с обязательной привязкой к выдаче**)
- Архивирование / восстановление поступлений
- Просмотр движения денежных средств за период

**Отчёты**

- Просмотр отчётов сотрудников (кроме чужих черновиков)
- Утверждение
- Возврат на доработку с комментарием
- Отклонение с комментарием
- Отметка **«Выплачено»** для отчётов-компенсаций (после утверждения)

**Приходы пользователей** (в «Получение денежных средств»)

- Просмотр приходов (фильтры: период, тип, статус, компания, поиск)
- На статусе **На проверке**:
  - **Деньги получены** → статус **Зачислен** + создание поступления в ДС
  - **Ожидать сдачу** → статус **К сдаче**
  - **Отклонить** с комментарием (доработка прихода **не** используется)
- На статусе **К сдаче**: **Отразить в движении ДС** → **Зачислен** + поступление

**Аудит**

- Просмотр журнала действий по системе

### Пользователь

**Свои средства (поступления / выдачи)**

- Просмотр своих поступлений и остатков
- Возврат остатка по своей выдаче (создаёт поступление у администратора с привязкой к выдаче)
- Архивирование полностью использованного своего поступления (`rest ≈ 0`)

**Приход**

- Просмотр своих записей прихода
- Регистрация прихода (черновик / отправка на проверку)
- Редактирование и удаление **черновика**
- Отзыв с проверки обратно в черновик
- Архивирование своего **зачисленного** прихода

**Отчёты**

- Создание отчёта (в т.ч. привязка к конкретной выдаче, если источник — выдача; либо компенсация из своих)
- Сохранение черновика
- Отправка на проверку
- Редактирование черновика и отчёта **«На доработке»**
- Отзыв с проверки обратно в черновик
- Удаление своего черновика
- Просмотр сводки своих отчётов
- Прикрепление чека / QR

**Чего у пользователя нет**

- Управление людьми и паролями
- Справочники
- Выдачи / поступления «от имени организации»
- Согласование чужих отчётов и приходов
- Общий журнал действий системы
- Раздел «Движение денежных средств»

## 5. Сущности

### 5.1. Пользователь (`users`)

ФИО, email, телефон, роль, статус (**Активен** / **Заблокирован**), пароль, флаги сессии (`sessionEpoch`, `mustResetPassword`).

Удаление пользователя в прототипе не предусмотрено.

### 5.2. Выдача / поступление пользователю (`issues`)

Деньги организации, выданные сотруднику (или компании — ограниченный сценарий).

- **Целевая** (`issueKind: targeted`) — назначение из справочника обязательно.
- **Нецелевая** (`issueKind: untargeted`) — «Пополнение баланса» / «Иное».
- Статусы: **Активна** | **Архив**.
- У пользователя в UI называется **«Поступление»**.

Остаток:

```text
rest = amount − (сумма отчётов по этой выдаче + сумма активных возвратов/поступлений с issueId)
```

В остаток «заняты» отчёты со статусами, которые ещё учитываются по выдаче (не черновик и не отклонённый).  
В сводки входят только **активные** выдачи пользователю (не компании, не архив).

### 5.3. Отчёт (`reports`)

Фиксация расхода сотрудником.

Источники:

- **Из полученной выдачи** — обязательна привязка к `issueId`; уменьшает остаток выдачи.
- **Собственные средства (компенсация)** — без списания выдачи; после утверждения админ может отметить **Выплачено**.

Статусы:

```text
Черновик → На проверке → (Утверждён | На доработке | Отклонён)
Утверждён → Выплачено   (только для компенсации)
```

Дополнительно: пользователь может **отозвать** с проверки в черновик; удалить — только свой черновик.

### 5.4. Приход (`userIncomes`) — бизнес через сотрудника

Это **не** личный доход и **не** зарплата. Сотрудник регистрирует деньги **бизнеса**, принятые от имени компании.

| Тип | Код | Обязательные поля |
|---|---|---|
| Оплата от контрагента | `counterparty` | сумма, дата, компания, от кого, основание |
| Поступление по процедуре | `procedure` | сумма, дата, компания, процедура, основание |
| Продажа имущества компании | `asset_sale` | сумма, дата, компания, что продано |
| Иное бизнес-поступление | `other` | сумма, дата, компания, описание основания |

Статусы:

```text
Черновик → На проверке → (К сдаче | Зачислен | Отклонён)
К сдаче → Зачислен
Зачислен → Архив (опционально)
```

Правила:

- редактировать / удалить черновик — только автор;
- с проверки пользователь может отозвать → черновик;
- **доработка прихода не используется**: при отклонении создаётся новый приход;
- legacy-статусы `Принят` / `Активна` нормализуются в **Зачислен**;
- в пользовательских сводках учитываются **К сдаче** и **Зачислен**;
- в **Движение ДС** попадает только зачисление (через `receipts` + `incomeId`).

### 5.5. Поступление организации (`receipts`)

Запись в кассу администратора:

- от **пользователя** (возврат / сдача) — с выбором выдачи; сумма уменьшает остаток;
- от **компании** / иное;
- автосоздание при зачислении прихода пользователя (`creditUserIncome`).

Статусы: **Активна** | **Архив**. В движении ДС — только активные.

### 5.6. Справочники (`dicts`)

- Компании  
- Процедуры (дела; у процедуры может быть должник)  
- Назначения платежа  
- Статьи расходов  

Записи не удаляются — архивируются / восстанавливаются.

### 5.7. Журнал действий (`activityLog`)

Аудит: кто, когда, действие, объект, детали. Админ видит всё. Фильтр «свои действия» для пользователя в коде есть, но в меню пользователя раздела нет.

## 6. Жизненные циклы

### 6.1. Выдача и расход

```text
Админ создаёт выдачу (целевая / нецелевая)
        ↓
У пользователя появляется «Поступление» с остатком
        ↓
┌───────────────────────┬────────────────────────┐
│ Отчёт «из выдачи»     │ Возврат остатка        │
│ (привязка к issueId)  │ (поступление у админа  │
│ → проверка админа     │  с issueId)            │
└───────────┬───────────┴────────────┬───────────┘
            ↓                        ↓
     остаток выдачи уменьшается
            ↓
     при rest ≈ 0 пользователь может отправить поступление в архив
```

### 6.2. Приход (бизнес через сотрудника)

```text
Пользователь регистрирует приход (тип + компания + поля по типу)
        ↓
   Черновик ──сохранить──┐
        ↓                │
   На проверке ←─────────┘  (можно отозвать → черновик)
        ↓
   ┌────┴──────────────┬────────────┐
К сдаче          Зачислен      Отклонён
   │         (деньги уже у
   │          админа + запись
   │          в ДС)
   ↓
Зачислен ← админ: «Отразить в движении ДС»
   ↓
 (опционально Архив)
```

### 6.3. Отчёт

```text
Черновик → На проверке → Утверждён
                ↓              ↓
          На доработке    (компенсация → Выплачено)
                ↓
          снова На проверке
                ↓
            Отклонён
```

С проверки пользователь может **отозвать** в черновик.

### 6.4. Что сознательно вне продукта

- зарплата, премия, отпускные и аналогичные выплаты;
- личные доходы сотрудника «для себя»;
- полноценная ОСВ / 1С (движение ДС — управленческий реестр, не замена бухгалтерии).

---

## 7. Правила пользования контурами

1. Роль выбирается при создании человека: **Администратор** или **Пользователь**.
2. Права не смешиваются.
3. **Выдача** — деньги организации сотруднику под контроль остатка.
4. **Приход** — деньги бизнеса, принятые сотрудником; после проверки либо сразу **Зачислен** в ДС, либо **К сдаче**, пока деньги не сданы.
5. **Поступление у админа** — касса организации (возврат с выдачи **или** зачисление по приходу **или** от компании).
6. **Отчёт** — расход: либо списание выдачи, либо компенсация своих средств.
7. Удаление учётных операций не используется — только архив (и удаление черновиков документов автором).

## 8. Технический контур прототипа

| Что | Как |
|---|---|
| Стек | Статический фронт: `index.html`, `app.js`, `styles.css` |
| Состояние | В основном **в памяти** браузера (демо-сид при загрузке) |
| Persist | `localStorage`: `saldo_user_incomes_v1` (приходы), `saldo_session_epochs_v1` (кик сессий); `sessionStorage` — свёртка блоков и черновик auth-сессии |
| Сессия | После перезагрузки страницы нужен повторный вход; эпохи сессий сверяются между вкладками |
| Хостинг | GitHub Pages (`turmes66/saldo`) |

Это **прототип UX и бизнес-логики**, не бэкенд с реальной мультитенантностью и серверной авторизацией.

## 9. Изменения относительно ранней модели

| Было | Стало |
|---|---|
| «Иной доход» как личный дневник без согласования | **Приходы** — бизнес-поступления с типами и статусами |
| Отдельная вкладка админа «Приходы» | Блок **«Приходы пользователей»** внутри **«Получение денежных средств»** (плашки свёрнуты по умолчанию) |
| Простое «Принят / Отклонён» | **Деньги получены** → Зачислен + ДС; **Ожидать сдачу** → К сдаче → Отразить в ДС |
| Доход не в движении ДС | Зачисление создаёт поступление (`receipts`) с `incomeId` |
| Отчёты без жёсткой привязки к выдаче | Отчёт из выдачи привязан к `issueId`; остаток считается по выдаче |
| Возврат не бил по остатку | Возврат от пользователя с `issueId` уменьшает остаток |
| Зарплата / личное в продукте | Явно вне скоупа |
